ROPAD / TOKEN PAGES, VISUAL BUILDS AND RELEASE READINESS
Audit date: October 10, 2026 Pacific / October 11 UTC

READINESS
Local development release. Not ready for a public, real-money launch.
The four implementation/review passes are processed separately from activation,
production integration and full gameplay acceptance. Existing games and their
historical evidence are preserved. No real-fund transaction is an audit test.

WHAT IS IMPLEMENTED
- Prompt-only game planning with Opus 5.5 or GPT-6 Astra, within provider catalog
  availability and spending limits. No fallback to a cheaper planning model.
- Creator-controlled revisions and source/project downloads. Token holding alone
  does not grant edit access. Prompt revisions generate a new scene and do not
  merge manual Studio code changes.
- Separate concept art and thumbnail generation, with real Studio frames labeled
  as captures. Images are not evidence that the game was built or playtested.
- Saved concept pixels guide planning. Bounded scene lighting and noncollidable
  decorative blocks, spheres and cylinders with yaw rotation improve the tools
  available to the planner. Gameplay geometry remains axis-aligned and validated.
- Three actual worker views (overview, spawn, finish) carry job IDs, timestamps
  and hashes. Opus/Astra can review these images, save a public visual critique
  and request at most one separate improvement version under the same approved
  run/project budgets. That version receives its own assembly, smoke check and
  visual review. Existing scenes and creator edits are preserved.
- Bounded Start/Pause workflow, project/daily/run reservations, durable costs,
  unknown-charge holds, and a creator-review stop. Opening a page starts no work.
- Solana Devnet game-mint flow and wallet ownership, with signing and recovery.
  Devnet coins have no real market cap, trading pool or fee revenue.
- Locally constructed and simulated mainnet trades for verified supported Pump
  SOL bonding curves. Exact wallet-message and finalized-receipt verification.
  No public mainnet creation/linking flow or PumpSwap integration is enabled.
- Coin overview/chart plus right-hand buy/sell panel. Prices and market cap are
  in SOL from verified observations gathered during the browser session. No
  fabricated history, USD conversion, holders, volume or token value.
- Separate token, game and creator workspace routes. Game pages show saved
  artwork/captures and only open Roblox when a valid creator-supplied release
  URL exists. These links do not establish publication, ownership or access.
  Actual gameplay runs in Roblox Player; no embedded gameplay is simulated.
- Per-project compute accounting and inactive read-only fee-receipt verification.
  Recorded SOL distributions are not provider credit or a platform-token buyback.

FINAL AUDIT HARDENING
The final review addresses scene recycling, creator UI after wallet changes,
expired compute displays and durable launch intent storage. Regression evidence
and the full packaged test result are recorded in the companion handoff report.
Updated workers retire after one build. Existing geometry, scripts and creator
edits are never recycled or removed for a later build. Start a fresh worker on
a fresh empty unpublished place for each next build.
All pool claims require oneBuildPerStudio:true plus the supported dedicated
worker capabilities, so an old running worker cannot claim manual or agent jobs.
Visual runs and enhanced plans also require fresh visualReviewProtocol:1 workers.
The unversioned manual bridge cannot render enhanced plans. Legacy screenshots
remain viewable without being inferred to belong to current visual-review jobs.
Visual revision retries use a durable exact-input identity and return the same
child after interruption. Changed inputs or frame hashes fail closed. Scene
captures become immutable when their authenticated worker lease closes.

VERIFICATION SCOPE
The current full source suite reports 507 passed, 0 failed and 0 skipped. Tests
mock provider and chain responses and exercise authorization, signature/quote
checks, revision idempotency and crash recovery, frame hashes, image validation,
shared compute budgets, failed storage, accounting and worker plans. An HTTP
pipeline fixture verifies two plans and two visual reviews with actual image
payloads. Executable Luau fixtures verify reviewed generated logic, decorative
collision rules and safe template-spawn handling. These results do not certify
production security or prove live provider, chain or Studio gameplay success.
Token/play page tests also cover route changes, stale responses, ownership
invalidation, trade panel refresh, safe release links and image provenance.
Optional executable Luau fixtures need an official Luau CLI; set
PARALLAX_LUAU_PATH and ROPAD_LUAU_BIN to its absolute executable path before npm
test, enabling both worker and gameplay fixtures. The runtime
archive contains no node_modules, private state, encrypted credential files or
detected plaintext provider keys. Install dependencies from the pinned lockfile.
